# SAMURAI WATCH

サッカー男子日本A代表の非公式情報アプリです。スマートフォンとPCで試合日程、代表招集、登録選手、クラブ出場、負傷・復帰情報を確認できます。直近の試合結果をグラフにし、登録選手は名前・所属クラブ・ポジションで絞り込めます。

## ローカルで起動する

Python 3.10 以降で、次のコマンドをリポジトリのルートから実行します。ブラウザーで `http://127.0.0.1:8000/` が開きます。ビルドやPythonパッケージの追加、ホスティングの設定は不要です。

```sh
python3 scripts/run_local.py --open
```

Windows では `py -3 scripts/run_local.py --open` を使います。ポートが使用中なら `--port 8080` などを追加できます。

起動時と、その後は起動中3時間ごとに、試合・招集データとFIFA男子ランキングの取得を試みます。アプリの **更新情報 → 今すぐ取得** から手動でも取得できます。クラブ情報の取得には起動したコンピューターで環境変数 `API_FOOTBALL_KEY` を設定します。自動取得は起動時と約24時間ごとです。終了するには起動したターミナルで Ctrl+C を押します。

## スマートフォンからアクセスできるようにする

1. アプリのファイルを GitHub リポジトリの既定ブランチ `main` へ反映し、GitHub Actions を有効にします。
2. GitHub リポジトリの **Settings → Pages** で **Build and deployment → Source → GitHub Actions** を選びます。
3. **Actions → Deploy site to GitHub Pages → Run workflow** を実行します。成功すると、Pages の設定画面にスマートフォンでも開ける URL が表示されます。
4. **Refresh Japan fixtures and call-ups** を手動実行し、アプリの「更新情報」で JFA の試合日程と招集発表が取得できたか確認します。以後は1日3回（日本時間 6:47・12:47・18:47 ごろ）自動更新します。GitHub の混雑状況により、数分〜数十分遅れることがあります。

### ホーム画面に追加（アプリとして使う）

公開 URL をスマートフォンで開き、iPhone は Safari の **共有 → ホーム画面に追加**、Android は Chrome の **メニュー → アプリをインストール（ホーム画面に追加）** を選びます。アイコンから全画面のアプリとして起動し、スマートフォンでは画面下部のタブで切り替えます。一度開いたデータは端末に保存され、通信できないときも直近の内容を表示します（`sw.js`、`manifest.webmanifest`）。

更新ワークフローは取得した JSON を既定ブランチに保存します。ブランチ保護などで Actions による書き込みが禁止されている場合は、その運用に合わせて反映してください。Pages の公開範囲は GitHub のプランとリポジトリ設定に従います。

## データと更新

| 項目 | 出典と更新方法 |
| --- | --- |
| 試合日程、招集発表 | [JFA](https://www.jfa.jp/samuraiblue/) から発表の日付・概要・リンクを取得します。取得失敗時は直近のデータを保持し、画面で取得状態を確認できます。 |
| 試合結果 | JFA と [International football results](https://github.com/martj42/international_results) の公開データを使用します。 |
| FIFA男子世界ランキング | [FIFA](https://inside.fifa.com/fifa-rankings/world-ranking/men) の発表を確認し、トップ画面に順位、発表日、確認できた場合は前回比を表示します。取得に失敗した場合は保存済みの順位を保持します。 |
| 先発フォーメーション | `data/lineups.json` に登録された、出典で確認できた試合を表示します。ピッチ上の選手を選ぶとプロフィール、クラブ、負傷・復帰の情報を確認できます。 |
| 選手の写真 | 各選手の英語版 Wikipedia 記事と Wikidata から、自由ライセンス（CC BY / CC BY-SA / CC0）の写真を Wikimedia Commons で取得します。Wikidata の生年月日が `data/player-biographies.json` と一致した場合だけ採用し、同姓同名の別人を避けます。選手詳細に撮影者・出典・ライセンスを表示します。**Refresh player portraits** ワークフローが毎週月曜に新しい招集選手の写真を追加し、ローカル版は起動時と「今すぐ取得」でも確認します。写真がない選手は背番号またはイニシャルを表示します。 |
| 選手・監督 | 直近のJFA招集発表を保存資料から照合し、2026年W杯登録名簿とは別に表示します。監督には役割と報道日または最終指揮日を掲載します。 |
| 選手プロフィール | `data/player-biographies.json` に出典とともに生年月日、出身地、高校・育成年代、A代表デビュー、実績・受賞歴を保存します。出場を確認できた最古の試合は、デビュー日の裏付けがない場合に別の項目で表示します。 |
| クラブ出場、負傷 | 公開資料から確認した試合・負傷情報を掲載します。ローカル版は公式Fantasy Premier Leagueから対象選手のリーグ累計と公表された負傷情報の取得も試みます。対応範囲を広げる場合は任意でAPI-FOOTBALLを設定できます。 |
| 復帰日、復帰見込み | 所属クラブや JFA の発表で確認できた内容を `data/players.json` の選手別 `reports` に追加します。復帰日は出場記録や負傷名から推定しません。 |

選手を API-FOOTBALL で照合できない場合は、確認済みの `clubLatin`、`apiFootballTeamId`、`apiFootballId` を選手レコードに設定できます。クラブの移籍が確認された際には、表示と自動取得先の両方を更新してください。

公式の招集名簿をアプリに載せる場合は、`data/players.json` の `callups` に `id`、発表日の `date`、`title`、`source`（`label` と `url`）、`players` を追加します。`players` には確認できた全選手を入れ、同一選手には既存の `id` を使います。記事リンクは自動取得の対象ですが、招集者の個別名簿は手動で確認します。

レポートには `date`（`YYYY-MM-DD`）、`type`（`club`、`injury`、`return` のいずれか）、`title`、公式発表への `source`（`label` と `url`）を記録します。必要に応じて `summary` を追加できます。

トップページの画像は生成したイメージです。実在の選手や実際の試合・負傷を撮影した写真ではありません。

# NSX CARE（1991年式 Honda NSX NA1 アプリ）

`nsx/` フォルダーにある、1991年式 NSX（NA1）のための個人用アプリです。GitHub Pages で公開すると `https://<ユーザー名>.github.io/<リポジトリ名>/nsx/` で開けます。スマートフォンではホーム画面に追加して使えます。ローカルでは `python3 -m http.server` をリポジトリのルートで起動し、`http://127.0.0.1:8000/nsx/` を開きます。

| 画面 | 内容 |
| --- | --- |
| ホーム | 交換時期のお知らせ、点検状況、部品供給の最新の変化。愛車の写真を設定できます（端末内だけに保存）。 |
| 交換時期 | エンジンオイル（半年）、ミッションオイル（2年）、ブレーキフルード（2年）、タイヤ（5年）。交換日を入力すると次回交換日を計算し、**その1か月半前から**アラートを表示します。項目は追加できます。 |
| パーツ | カテゴリー別のパーツリスト。部品ごとに販売状況（販売中／復刻あり／廃番／要確認）・品番・メモを登録できます。品番はホンダ公式「継続供給中部品番号リスト」と自動照合します。 |
| 不具合 | NA1 で知られる典型的な不具合と、その整備チェックリスト（チェックした日付を記録）。 |
| 車両情報 | 基本スペック、車両の歴史、開発経緯・開発者の来歴。 |

## 1日1回の更新

- **Refresh NSX parts supply** ワークフローが毎日（日本時間 5:23 ごろ）ホンダ公式の Honda Heritage Works / NSX 関連ページを確認し、内容の変化と継続供給中リストの部品番号を `nsx/data/supply.json` に保存します。取得に失敗した場合は前回の内容を保持します。
- アプリは日付が変わると最新のデータを取り直し、交換アラートも再計算します。
- 車両情報・不具合・パーツの初期内容は `nsx/data/vehicle.json` を編集すると更新されます。

写真は Wikimedia Commons で公開されている NA1 の自由ライセンス画像（CC0 / CC BY / CC BY-SA）を縮小して `nsx/img/` に収録しています。撮影者・ライセンスは `nsx/data/photos.json` と、アプリの「車両情報 → 写真クレジット」に記載しています。ホンダの公式画像やロゴは使用していません。

交換日・チェック・部品メモはその端末のブラウザーに保存されます。機種変更の前に「交換時期 → データを書き出す」でファイルに保存し、新しい端末で「読み込む」を使ってください。部品の在庫・価格・廃番は必ずホンダ販売店で確認してください。

# ビカク日記（ビカクシダ成長記録アプリ）

`fern/` フォルダーにある、育てているビカクシダの成長を記録する個人用アプリです。GitHub Pages で公開すると `https://<ユーザー名>.github.io/<リポジトリ名>/fern/` で開けます。スマートフォンではホーム画面に追加して使えます。ローカルでは `python3 -m http.server` をリポジトリのルートで起動し、`http://127.0.0.1:8000/fern/` を開きます。

| 画面 | 内容 |
| --- | --- |
| 株 | 株ごとに名前・品種・入手日・置き場所・水やり間隔を登録します。株のページで写真を取り込み（撮影日は写真の情報から自動で入ります）、月ごとに並べて「最初」と「最新」を見比べられます。水やり・ソーキング・肥料・葉水も記録できます。 |
| 水やり | 前回の水やりから株ごとの間隔を過ぎた株を上に並べ、1タップで記録します（取り消し可）。目安を過ぎた株はまとめて記録できます。 |
| 害虫 | 害虫・病気の発見（種類・発見日・症状・写真）と、駆除や対応の履歴、状況（対応中／経過観察／解決）を株ごとに記録します。 |
| ガイド | 光・風通し・水やり・温度・肥料・板付けなどの育成ポイントと、主な病害虫（カイガラムシ、コナカイガラムシ、ナメクジ、ハダニ、アザミウマ、アブラムシ、成長点の腐れ、黒い斑点、葉焼け）の症状と対策。内容は `fern/data/guide.json` を編集すると変わります。 |
| 保存 | 記録と写真をまとめたバックアップファイルの書き出しと読み込み、保存容量の確認。 |

記録と写真はその端末のブラウザー（IndexedDB）だけに保存され、外部には送信しません。写真は取り込み時に長辺1600pxへ縮小します。機種変更の前や定期的に「保存 → 書き出す」でバックアップしてください。iPhone では Safari で開いたときとホーム画面から開いたときで保存場所が別になるため、どちらか一方で使い続けてください。薬剤は必ずラベルの適用植物と使用方法を確認してください。

## Claude Code skills

`.claude/skills/` holds project skills shared with everyone using Claude Code here. Each skill stays inside one section of the repo; when another section needs it, call it by name (for example `/refresh-nsx-data`).
- `skill-creator` — create, test and improve skills (`/skill-creator`).
- `refresh-samurai-data` — refresh the Japan national team data in `data/` and `assets/portraits/`.
- `refresh-nsx-data` — refresh the NSX parts-supply data in `nsx/data/`.

To add a skill, ask Claude「skill-creator で○○のスキルを作って」and keep it in `.claude/skills/<name>/`.
